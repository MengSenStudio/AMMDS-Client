## 7. 本轮发现并修复的问题

| # | 问题 | 影响 | 处理 |
| --- | --- | --- | --- |
| 1 | Client API 只有列表 / 详情 / 章节列表，**没有章节正文与章节图片接口** | 阅读器无数据来源 | 服务端新增 `GET /novels/{id}/chapters/{cid}`、`GET /comics/{id}/chapters/{cid}`，并给出纯文本正文、章节序号与相邻章节 |
| 2 | 封面 / 海报 / 章节图片在库中为**仓库相对路径**（如 `data\images\…`），客户端无法直接加载 | 列表与详情图片全部 404 | 服务端 `ClientResourceUrls` 归一化为 `/api/pub/resource/image?path=…`；客户端 `ResourceUri` 对旧方言做同样兜底（真实库验证：444KB / 248KB / 579KB 图片均可下载） |
| 3 | 既有公开接口的小说详情结构为 `{book:{…}, chapters:[…]}`，客户端按平铺结构解析 | 公开方言下小说详情标题为空 | `ContentDetailDto` 兼容 `book` / `album` / `detail` 嵌套（真实库验证：标题、作者、1677 章目录均正确） |
| 4 | 影视 / 人物的 `poster` 为**多值列表**，客户端按字符串解析 | 生成 `"[a.jpg, b.jpg]"` 伪地址，封面加载失败 | 新增 `JsonReader.firstString`，多值取首个有效地址（真实库验证：影视封面 579KB 成功下载） |
| 5 | 公开方言字段为驼峰（`titleCn` / `originalTitle` / `plotCn` / `chapterCount` / `director`） | 影视标题退化为 ID、简介为空、集数为空 | DTO 增加驼峰兼容与 `firstString` 兜底 |
| 6 | 详情页缺少扩展信息与关联内容，章节点击仅弹出「后续版本提供」提示 | 详情页信息不完整、阅读器入口不可用 | 服务端下发 `attributes` / `gallery` / `related`；客户端新增属性表、图集、关联作品区块，章节与「开始 / 继续阅读」均跳转阅读器 |
| 7 | 阅读设置与进度无持久化 | 每次阅读都从第一章开始 | 新增 `ReadingRepository`（本地普通配置）：字号 / 行距 / 背景、漫画阅读模式、按内容维度的阅读进度与最近阅读 |
| 8 | （测试设施）PowerShell 以 ASCII 提交请求体，写入的中文测试数据变成 `?` | 首轮真实后端用例误判为「正文未渲染」 | 新增 `scripts/seed_e2e_content.ps1`，显式以 UTF-8 字节提交并回读校验 |
| 9 | （测试环境）并行运行的服务端实例占用 H2 文件库，导致 `mvn test` 中 60 个 Spring 上下文用例报错 | 误判为服务端回归失败 | 停止实例后重跑：**593 项全部通过**，确认为环境锁冲突而非代码问题 |

## 8. 界面与交互验证要点

* **小说阅读器**：目录弹层（章数统计、当前章高亮、点击跳转）、上一章 / 下一章（正文底部与底栏双入口，首尾章自动禁用）、字号 ±2、行距 ±0.2、浅色 / 米黄 / 夜间三套配色、点击正文切换导航栏显隐、退出后按进度恢复章节与滚动比例。
* **漫画阅读器**：翻页模式（左 / 中 / 右三区点击：上一页 / 显隐导航 / 下一页）、双指缩放（1~4 倍）、连续滚动模式、页码指示（`x / y 页`）、章节目录、上一话 / 下一话、图片加载中骨架与失败占位。
* **详情页**：四类内容共用一套渲染，按类型展示扩展属性（人物身高 / 血型、影视分辨率 / 语言、小说出版社、漫画卷号等）、图集横向列表、演员关联作品横向卡片（点击进入影视详情）。
* **国际化**：新增 60+ 条中英文本地化文案（阅读器、属性标签），`flutter gen-l10n` 生成通过。

## 9. 复现步骤

```bash
# 1) 编译并启动测试服务端（测试库 + 测试账号）
cd <repo>
ADMIN_PASS=ammds-e2e-pass mvn -o -B spring-boot:run \
  "-Dspring-boot.run.arguments=--server.port=18099 \
   --ammds.scheduler.enable=false --ammds.monitor.enable=false \
   --spring.datasource.url=jdbc:h2:file:./db/ammds-client-e2e;DB_CLOSE_DELAY=-1"

# 2) 写入端到端测试数据（小说 + 漫画 + 章节图片）
$env:AMMDS_E2E_ADMIN_PASS='ammds-e2e-pass'
pwsh -File scripts/seed_e2e_content.ps1 -BaseUrl http://127.0.0.1:18099

# 3) 客户端各层测试
cd client
flutter analyze
flutter test test
flutter test integration_test/e2e_test.dart -d windows
flutter test integration_test/live_backend_test.dart
flutter test integration_test/live_ui_test.dart -d windows
AMMDS_E2E_PORT=18099 flutter test integration_test/live_public_backend_test.dart

# 4) 服务端全量测试（注意：需先停止正在运行的服务端实例，避免 H2 文件库被占用）
cd <repo>
mvn -o -B test -DskipTests=false
```

## 10. 残余风险与后续建议

| 项 | 说明 | 建议 |
| --- | --- | --- |
| 移动端真机 | 本轮仅在 Windows 桌面执行 UI 端到端；Android / iOS 依赖原生安全存储与网络栈，未在真机验证 | 在真机执行 `flutter test integration_test/e2e_test.dart` 与 `live_ui_test.dart` |
| 影视播放 / 离线下载 / 收藏 | 明确不在本轮范围 | 作为后续迭代排期 |
| 阅读进度服务端同步 | 客户端已接入：`clientV1` 用 `/api/client/v1/novels/{id}/progress`、`/comics/{id}/progress`；`ammdsPublic` 复用既有的 `/api/pub/novel/progress`、`/api/pub/comic/progress`；本地优先 + 服务端后写者胜 | 依赖服务端 `updated_at` 判定新旧；跨设备时钟偏差可能影响取舍 |
| 超大章节目录 | 真实数据存在 1677 章的小说；详情页按 20 章一页渲染并提供「加载更多章节」，阅读器目录使用懒加载列表 | 如仍嫌渲染压力大，可把详情页章节改为虚拟滚动 |
| 漫画超长章节 | 连续滚动模式一次构建整章图片列表 | 数据量增大后可改为懒加载 + 预加载窗口 |
| 封面为失效远端地址 | 刮削数据可能指向已失效的远端图片 | 客户端已使用占位图兜底；后续可增加资源可用性探测与本地缓存 |

### 11.4 Web 端的固有限制（浏览器能力决定，非缺陷）

| 项 | 说明 |

### 11.5 自动化环境的已知限制（不影响真实用户）

自动化浏览器所在 WebView 的 `document.hasFocus()` 恒为 `false`，Flutter Web 会因此忽略
语义输入框上的 `input` 事件，导致「直接向 DOM 输入框赋值」无法驱动应用内的输入框。
走查时通过「先向 `<flutter-view>` 派发 pointer 事件让控件获得焦点，再写入文本」绕过；
真实用户在浏览器中键入时文档拥有焦点，不受此限制。

## 15. 播放器画面手势（2026-09-21）

在 `MediaPlayerPage` 上补齐「常见播放器」的画面手势与配套反馈，并把操作栏的
自动隐藏规则统一为「任何状态下无操作 3 秒即收起」——第 14 节遗留的
「片尾 `ended` 时控件常显」一并消除。

### 15.1 本轮改动

| 能力 | 实现 |
| --- | --- |
| 单击画面 | 播放 / 暂停，并唤出操作栏 |
| 双击两侧 | 左半屏后退 10 秒 / 右半屏前进 10 秒（落点按画面中线分侧） |
| 横向滑动 | 拖动定位进度，刻度与底部进度条一致（满屏宽度 ≈ 整段时长）；定位期间操作栏保持可见 |
| 左右半屏上下滑动 | 左半屏调亮度、右半屏调音量；滑过「画面高度的 70%」等于走完整个可调区间 |
| 手势浮层 | 画面中央浮层反馈：音量 / 亮度百分比 + 进度条，或定位目标时间 + 总时长 / 双击进退量，900ms 后自动消失 |
| 亮度 | 不碰系统亮度（需原生插件与权限），改为在画面上铺一层黑色遮罩（可调区间 20% ~ 100%）；**当日后续改为原生插件，见第 16 节** |
| 操作栏自动隐藏 | 起播、暂停、缓冲进出、播放结束都重新计时，3 秒无操作即收起；点击 / 滑动画面、移动鼠标、任意快捷键唤出 |

判定方式（关键）：单击 / 双击**不用** `GestureDetector.onTap` + `onDoubleTap`，
而是由 `Listener` 的原始指针事件自行判定（`kDoubleTapTimeout` 判定窗口、
`kDoubleTapSlop` 落点容差、`kTouchSlop` 区分点击与拖动），拖动仍交给框架的
拖动识别器。原因见 15.3。

### 15.3 本轮发现并修复：单击画面静默失效

| # | 现象 | 根因 | 处理 |
| --- | --- | --- | --- |
| 1 | 浏览器实测「单击画面」完全没有反应：`video.paused` 不变、操作栏也不出现；而双击、拖动都正常 | `onTap` 与 `onDoubleTap` 同时注册时，框架把单击判定推迟到双击超时之后，且**按下不足 100ms 的快速点击不会触发任何回调**：TapGestureRecognizer 的 `didExceedDeadline`（100ms）在指针抬起时被 `stopTrackingPointer` 取消，`_checkUp` 又因尚未赢得竞技场而提前返回（框架用例 `Unfinished DoubleTap does not prevent competing Tap` 亦记录「首个单击赢得竞技场也不回调 onTap」）。而鼠标单击的典型按压时长正是 50~150ms | 单击 / 双击改为在 `Listener` 上按原始指针事件自行判定（见 15.1）；拖动仅在实际越过 `kTouchSlop` 后才生效，避免鼠标单击时的抖动被当成滑动 |

> 修复前后在同一构建/同一浏览器下的对照：修复前 6 组单击（含 2s 长窗口采样）全部
> `paused` 不变；修复后 0ms 快速单击与 120ms 拟人化单击均正常反转播放状态。

## 16. 播放器亮度改为原生插件（2026-09-21）

按「尝试调用原生插件、不支持的平台忽略、不做特殊处理」的要求，把第 15 节的
「画面黑色遮罩」换成原生插件 `screen_brightness` 的应用亮度调节。

### 16.1 改动

| 项 | 说明 |
| --- | --- |
| 依赖 | 新增 `screen_brightness`（+ android / ios / macos / windows / ohos 各平台实现）；Android 的 `WRITE_SETTINGS` 是「改系统亮度」才需要的权限，本实现只改**应用**亮度，**不需要任何权限、未改任何清单文件** |

原生调用集中在 `MediaPlayerPage` 的 `_loadBrightness` / `_applyBrightness` /
`_resetBrightness` 三个方法，全部 `try/catch` 忽略失败。
